# Finance Function Reference

This document is generated from the extension registration surface in `src/` and the executable SQL coverage in `test/sql/`. All functions live in the `fin_` namespace and use standard DuckDB types such as `DOUBLE`, `VARCHAR`, `DATE`, `TIMESTAMP`, `LIST`, `STRUCT`, and table results.

## Usage Conventions

- Load the extension before use. Most users can run
  `INSTALL finance FROM community; LOAD finance;`; for source builds, use the
  repository Makefile targets to build and load the unsigned local extension
  during validation.
- Scalar functions are called in ordinary `SELECT` expressions.
- Aggregate functions and aggregate macros are called over grouped rows, for example `SELECT fin_total_return(r) FROM returns;`.
- Table functions and bind-replace functions appear in `FROM`, for example `SELECT * FROM fin_calendar('weekday', DATE '2026-05-04', DATE '2026-05-08');`.
- `make check` verifies this reference against every registered `fin_*`
  function and verifies that every registered function appears in the gold SQL
  tests. The checks scan split `.cpp` and `.inc` source units under `src/`.

## Scalar Inputs, Units, And Errors

- Configuration strings such as compounding, day count, option kind, exercise
  style, Greek units, tick mode, calendar, and time zone are validated. An
  unknown value raises an error that starts with the function name, for example
  `fin_yearfrac: unknown day-count convention 'ACT/999'`. Constant strings are
  parsed once per chunk.
- Numeric domain failures, such as a non-positive volatility, an expired option
  where no limit is defined, a rate at or below -100%, or a solver with no root,
  return `NULL` for that row and never abort the query.
- Integer parameters (frequency, periods, binomial steps, iteration limits,
  business-day offsets) take `BIGINT`, so `INTEGER` and `BIGINT` columns both
  bind.
- Date parameters accept `DATE`, `TIMESTAMP`, or `TIMESTAMPTZ` and drop the
  time of day. `TIMESTAMPTZ` converts in the session `TimeZone`, which needs the
  ICU extension (bundled with most DuckDB clients).
- Option functions take annual decimal rates, volatilities, and dividend yields,
  and time to expiry in years. Theta, charm, and color are calendar-time decay
  (-d/dT). Vega and rho accept `'raw'` (default) or `'market'` (per 1 point,
  raw / 100); theta accepts `'year'` (default), `'day'` (/365), or
  `'trading_day'` (/252).
- Native scalar functions take optional arguments by position. Only SQL macros
  such as `fin_option_spec` accept `name := value` arguments.

### Returns, Risk, And Statistics

Conventions for the returns and risk functions (0.3.0):

- Native aggregates (`fin_volatility`, `fin_sharpe`, `fin_sortino`,
  `fin_downside_deviation`, `fin_total_return`, `fin_beta`, `fin_var`,
  `fin_cvar`, the drawdown family, `fin_trimmed_mean`, `fin_winsorized_mean`,
  `fin_weighted_quantile`, `fin_garch11_forecast`, `fin_yang_zhang_vol`,
  `fin_stability`, EWMA, IV rank/percentile, outlier count, quantile spread,
  bipower variation) take positional arguments. DuckDB binds native arguments
  by position, so `name := value` on a constant is rejected with an error;
  macros keep named parameters. These aggregates also run as window functions
  (`OVER (PARTITION BY .. ORDER BY .. ROWS BETWEEN ..)`); fixed-state metrics
  use DuckDB's segment tree and history-keeping ones keep a single frame.
- Order-dependent aggregates need `ORDER BY` inside the call
  (`fin_max_drawdown(r ORDER BY ts)`) or a window `ORDER BY`. Order-dependent
  macros take the ordering column explicitly (`fin_calmar(r, ts)`,
  `fin_recovery_factor(r, ts)`, `fin_zscore_last(x, ts)`). Break ties in the
  ordering key: rows with equal keys have no defined relative order.
- Risk-free rates, MAR, required returns and thresholds (`fin_sharpe`,
  `fin_sortino`, `fin_downside_deviation`, `fin_upside_deviation`,
  `fin_semivariance`, `fin_omega_ratio`, `fin_hit_ratio`, `fin_alpha`,
  `fin_treynor_ratio`, `fin_jensen_alpha`) are annual decimal rates converted
  to per-period rates geometrically: `(1 + rate)^(1 / annualization) - 1`.
- A group containing a NaN or infinite observation (or a domain-invalid one,
  such as a return below -1 for compounding and drawdowns) returns `NULL` for
  that group instead of aborting the query. `fin_outlier_count` is the
  documented exception and ignores non-finite values. Invalid constant
  configuration (unknown method, confidence outside (0, 1), non-positive
  annualization) raises an error whose message starts with the function name.
- Compounding (`fin_total_return`, `fin_cagr`, `fin_nav`, `fin_log_nav`,
  `fin_geometric_return`, `fin_calmar`) runs in log space with `log1p`/`expm1`,
  so long series do not overflow intermediate wealth.

`fin_stable_var` and `fin_stable_stddev` use denominator `count(x) - ddof` for
any finite non-negative `ddof`; an exhausted denominator returns `NULL`.
Downside/upside deviation, semivariance, and hit/win/loss rates skip NULL
observations. Beta, alpha, Treynor, capture ratios, and VWAP use complete
input pairs. Drawdown ratios track wealth relative to the running peak to avoid
overflow; the positive `initial_nav` scale does not change those ratios.
Weighted moments that overflow return `NULL` rather than a fabricated zero
variance.

## Technical indicator conventions

The trend, momentum, oscillator, band and SAR indicators (`fin_sma`, `fin_wma`,
`fin_ema`, `fin_dema`, `fin_tema`, `fin_trima`, `fin_t3`, `fin_kama`,
`fin_hma`, `fin_linearreg`, `fin_linearreg_slope`, `fin_linearreg_intercept`,
`fin_tsf`, `fin_mom`, `fin_roc`, `fin_rocp`, `fin_rocr`, `fin_rocr100`,
`fin_rsi`, `fin_cmo`, `fin_macd`, `fin_apo`, `fin_ppo`, `fin_trix`,
`fin_stoch`, `fin_stochrsi`, `fin_willr`, `fin_cci`, `fin_bbands`,
`fin_keltner`, `fin_donchian`, `fin_stddev`, `fin_var_indicator`,
`fin_aroon`, `fin_aroonosc`, `fin_sar`, `fin_sarext`), the volatility,
directional and volume indicators (`fin_true_range`, `fin_atr`, `fin_natr`,
`fin_plus_dm`, `fin_minus_dm`, `fin_plus_di`, `fin_minus_di`, `fin_dx`,
`fin_adx`, `fin_adxr`, `fin_mfi`, `fin_ultosc`, `fin_obv`, `fin_adosc`) and
the ordered microstructure estimators `fin_roll_spread` and `fin_vpin` are
native, order-dependent aggregates that follow the TA-Lib definitions, seeding
and warm-up (Roll and VPIN follow their papers). The gold tests compare them
with TA-Lib 0.6 (Python `ta-lib` 0.8.1). `fin_vwap`, `fin_ad_line`,
`fin_amihud_illiquidity`, `fin_kyle_lambda` and `fin_volume_profile` do not
depend on row order and need no `ORDER BY`; `fin_twap` orders by its own
timestamp argument.

- Ordering. `fin_rsi(close, 14 ORDER BY ts)` returns the indicator value at the
  last row of the ordered group. As a window function,
  `fin_rsi(close, 14) OVER (PARTITION BY symbol ORDER BY ts ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)`
  returns the TA-Lib series row by row. Any other frame computes the indicator
  from the frame rows only: bounded indicators (moving averages over a fixed
  lookback, momentum, stochastics, CCI, bands, Aroon, true range, MFI,
  ULTOSC) match the running series once the frame holds their lookback, and
  recursive indicators (EMA family, KAMA, RSI, CMO, MACD, TRIX, StochRSI,
  Keltner, SAR, ATR, NATR, DM, DI, DX, ADX, ADXR, OBV, ADOSC, Roll, VPIN)
  restart at the frame start. Rows with equal ordering keys are processed in an unspecified order,
  so add a tiebreaker such as `ORDER BY ts, seq`.
- Calls without an order. When DuckDB aggregates unordered input in parallel,
  the call fails with `rows reached the aggregate in an undefined order`
  instead of merging partial series. Frames that cover the whole partition
  (`OVER (PARTITION BY symbol)` or `ROWS BETWEEN UNBOUNDED PRECEDING AND
  UNBOUNDED FOLLOWING`) are evaluated by DuckDB without row order; use the
  grouped form for the last value instead.
- Warm-up. Rows before the TA-Lib lookback return `NULL` (the whole `STRUCT`
  for struct results). Each reference row states where the first value
  appears; rows are counted from 0 after skipped rows.
- Parameters. Parameters are positional (`name := value` is rejected) and
  optional from the right. Integer parameters accept `INTEGER`, `BIGINT` and
  integral `DECIMAL`/`DOUBLE` values from 1 to 100000 (2 where TA-Lib requires
  it). A `NULL`, out-of-range or non-integral value raises an error that starts
  with the function name. Parameters are usually constants; a column parameter
  (for example `GROUP BY period`) must be constant within each group or window
  partition.
- `NULL` and non-finite input. Rows with a `NULL` input are skipped. A `NaN` or
  infinite input makes a bounded indicator `NULL` while that row is inside its
  lookback and a recursive indicator `NULL` for the rest of the series.
- Division conventions follow TA-Lib for flat inputs: RSI and CMO return 0 when
  prices do not move; the stochastic fastK, StochRSI and Williams %R return 0
  for a zero high-low range; CCI returns 0 for zero mean deviation. Ratios with
  a zero denominator (`fin_roc`, `fin_rocp`, `fin_rocr`, `fin_rocr100`,
  `fin_ppo`, `fin_trix`) return `NULL` where TA-Lib returns 0.
- Performance. State is bounded by the periods. Running windows update
  incrementally; sliding windows replay at most the lookback of bounded
  indicators. Results are bit-identical for any thread count.

## Trend precision with large absolute levels

For `fin_linear_trend`, subtract a group-specific origin from both axes before
fitting when absolute levels are large relative to their variation. The executable
source-build recipe `examples/linear_trend_centered.sql` filters finite pairs,
computes origins with window functions, and fits each group in a separate step.
Groups with no finite pairs are absent from that recipe's output.

The fit uses DOUBLE arithmetic. In a 101-point synthetic series with slope 2,
alternating quarter-unit noise, and both axes offset by `1e15`, the uncentered
slope standard error was `0.0008786840531774002`. Centering produced
`0.000861770574046724`, compared with the exact-arithmetic reference
`0.000861770574038108`. The uncentered relative error was about 1.96% on
DuckDB v1.5.5 and v1.6.0-dev11514. This is one reproducible case, not an error bound.

Keep both origins with the fit. Its intercept describes shifted coordinates:
`y_predicted = y_origin + trend.intercept + trend.slope * (x_new - x_origin)`.
Centering cannot recover precision lost when converting inputs to DOUBLE, and
does not eliminate residual-variance cancellation for nearly perfect fits.
For timestamp axes, prefer elapsed time in the units needed by the analysis.
